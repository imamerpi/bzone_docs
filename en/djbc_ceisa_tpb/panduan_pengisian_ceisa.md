# CEISA 4.0 Filling Guide for Bonded Storage Facilities (djbc_ceisa_tpb)

This document is a **User Guide** for Exim Operations, Logistics, Customs Brokers (PPJK), and Company Customs Staff when filling in each tab of the CEISA 4.0 customs declaration form for **Bonded Storage Facilities (Tempat Penimbunan Berikat - TPB)**. This guide is non-technical and is structured based on Indonesian customs best practices.

---

## 1. Basic Rules & Key Filling Principles

Before clicking the **Confirm** button on a TPB document, make sure you understand three golden rules to prevent the document from being **rejected** by the Customs server.

### 1.1 CIF Value and Goods Value Must Not Be Zero (0)

The CEISA server automatically rejects documents with **CIF = 0** or **unit price = 0**, as this violates the *transaction value* principle under **Indonesian Customs Law No. 17 of 2006**. Customs authorities consider any goods circulating within a customs area to have an economic value, no matter how small.

### 1.2 Handling Free Samples, Gifts, Warranty Items, and Free of Charge (FOC)

For special cases such as free samples, promotional gifts, warranty replacements, or **Free of Charge (FOC)** shipments, do NOT leave the value blank or write zero. Follow these steps:

* Use a **Proforma Invoice** clearly titled: **"Value for Customs Purposes Only"**.
* Assign a reasonable reference value based on **market price**, **previous invoices**, or **production cost data**.
* Add a clear remark such as **"FOC"** or **"Free of Charge"** in the additional information field so Customs auditors understand the context.

### 1.3 Weekly Tax Exchange Rate (NDPBM KMK)

All customs calculations in Indonesian Rupiah **must** use the **Tax Exchange Rate (Kurs Pajak)** set weekly by the Minister of Finance (commonly known as **NDPBM KMK**). Do **not** use the bank's selling rate or commercial transaction rates.

> [!TIP]
> The applicable exchange rate is the rate on the **document registration date** in CEISA. Make sure the weekly rate is updated in your BZone system through the **Kurs Pajak Pabean** menu before creating any new TPB document.

## 2. Step-by-Step Form Filling Procedure

Open the **CEISA Connector > Customs > TPB** menu, then select the document type you want to create. Follow each step below in order.

### Step 1: Document Header Tab

This tab is the main identity of your customs declaration.

* **26-Digit Submission Number (Nomor Aju)**: Automatically generated by the system when you save the draft.
* **Supervising Customs Office**: Select according to your TPB permit (e.g., `040300` for Bonded Zone Supervision Office).
* **Customs Document Type**: Select based on the transaction purpose:

  ![BC Document Type Selection](/assets/images/ceisa_tpb_header.png)

  | BC Code | Brief Purpose |
  |---|---|
  | **BC 2.3** | Import of goods into TPB (raw materials / capital goods from overseas). |
  | **BC 2.5** | Sale / delivery of finished goods from TPB to the local market. |
  | **BC 4.0** | Local purchase into TPB with VAT non-collected. |
  | **BC 4.1** | Return / delivery from TPB to TLDDP (Domestic Customs Area). |
  | **BC 2.7** | Inter-TPB transfer. |
  | **BC 2.6.1 / 2.6.2** | Subcontract release / return. |

### Step 2: Entities Tab

Entities are the parties involved in a transaction. The system auto-assigns priorities, but you must confirm the following data:

* **TPB Operator (Series 1)**: Mandatory and automatically set as the primary entity. The 16-digit NPWP (Tax ID), NIB (Business Identity Number), and TPB permit number must be valid.
* **Cargo Owner**: The legal owner of the goods (may be the same as the TPB Operator).
* **Consignee**: The party receiving the goods at destination.
* **Shipper**: The overseas supplier (for imports) or local supplier (for BC 4.0/4.1).
* **API Type**: Select **API-P** (Notification of Goods Import) for general imports, or according to the licensing document issued by the Customs Office.

  ![Customs Entity Form](/assets/images/ceisa_tpb_entitas.png)

### Step 3: Supporting Documents Tab

This tab contains the supporting documents for the transaction. **Series ordering is critical** because the CEISA server validates by priority:

1. **Commercial Invoice** - **Mandatory Series 1**. For proforma invoices, use document type `PROFORMA INVOICE`.
2. **Bill of Lading (B/L) or Air Waybill (AWB)** - **Mandatory Series 2** for goods moving through seaports/airports.
3. **Other Supporting Documents** - Placed after Series 2, such as: Packing List, Certificate of Origin (Form E / Form D), Contract, and Spare Part List.

  ![Supporting Document Series Order](/assets/images/ceisa_tpb_dokumen_pelengkap.png)

> [!IMPORTANT]
> If the Invoice and B/L/AWB are not in Series 1 and Series 2, the document will be rejected automatically by the Customs system.

### Step 4: Transport Tab

Fill in the physical movement of goods from origin to destination.

* **Transport Mode**: Select by mode: Sea / Air / Land.
* **Transport Vehicle Name**: Vessel name / flight number / vehicle plate number.
* **Country Flag Code**: Use the 2-letter code per **ISO Alpha-2 Capital** standard, e.g., `ID` (Indonesia), `SG` (Singapore), `CN` (China), `JP` (Japan).
* **BC 1.1 Manifest Number**: Enter the manifest number from the shipping line or forwarder agent.

  ![Transport Vehicle Data](/assets/images/ceisa_tpb_pengangkut.png)

### Step 5: Packaging & Container Tab

Fill in the physical packaging details of the goods.

* **Quantity and Type of Packaging**: Use CEISA standard packaging codes, e.g., `CTN` (Carton), `PK` (Pack), `PLT` (Pallet), `BG` (Bag), `DR` (Drum).
* **Quantity per Type**: Enter the package count, e.g., `10` for `10 Cartons`.
* **Container Number**: Enter the **11-digit container number** as printed on the container (4-letter prefix + 7 digits). Specify the container size and type (20ft, 40ft, 45ft).

  ![Packaging & Container Details](/assets/images/ceisa_tpb_kemasan.png)

### Step 6: Transaction & Financial Tab

This tab is the **heart of customs calculation** since it defines the basis for Import Duty and taxes.

* **Currency Code**: Select the foreign currency code based on the invoice, e.g., `USD`, `CNY`, `EUR`, `JPY`.
* **FOB Value (Free on Board)**: The value of goods at the loading port.
* **Freight**: The transportation cost from origin warehouse to the destination port.
* **Insurance**: The shipment insurance premium.
* **CIF Value**: Calculated automatically by the system.
* **Delivery Price (Harga Penyerahan)**: Delivery value in Rupiah for local transactions (BC 4.0/4.1/2.5).
* **Date and KMK Exchange Rate**: Auto-populated based on the document date and the active tax rate master.

  ![Financial & CIF Tab](/assets/images/ceisa_tpb_keuangan.png)

### Step 7: Goods & Raw Material Details Tab

Fill in the itemized details of each goods line.

* **HS Code 8 Digits**: Select per the **Indonesian Customs Tariff Book (BTKI)**, e.g., `8473.30.90` for computer parts.
* **Goods Description**: Write a clear description matching the physical goods, to ensure smooth inspection.
* **CEISA Unit**: Select from standard unit codes, e.g., `PCE` (Piece), `KGM` (Kilogram), `MTR` (Meter), `LTR` (Liter).
* **Quantity & Value**: Enter the quantity and the CIF value per item.
* **Raw Material Conversion (BC 2.5)**: For local sales of finished goods processed from imported raw materials (BC 2.3), the system automatically pulls **Raw Material Usage History** as the basis for Import Duty and tariff calculation.

  ![Goods Details & Tariff](/assets/images/ceisa_tpb_barang.png)

## 3. Customs Calculation Methods & Formulas

This section explains the simple formulas you can use to **double-check** the duties and taxes before the document is sent.

### 3.1 Basic Calculation Formulas

| No | Component | Formula |
|---|---|---|
| 1 | CIF Value (Foreign) | **CIF = FOB + Freight + Insurance** |
| 2 | CIF Value (IDR) | **CIF IDR = CIF Foreign x KMK Tax Rate** |
| 3 | Import Duty (BM) | **BM = Tariff % x CIF IDR** |
| 4 | Import Value (Tax Base) | **Tax Base = CIF IDR + Import Duty** |
| 5 | Import VAT (11%) | **VAT = 11% x Tax Base** |
| 6 | Article 22 Income Tax | **PPh 22 = 2.5% x Tax Base** (if holding an API) or **7.5% x Tax Base** (if non-API) |

> [!TIP]
> The **Tax Base** is the foundation of VAT and Article 22 Income Tax assessment. Make sure all components above it are calculated correctly.

### 3.2 Practical Numerical Case Study

Below is a real-world example to help operational staff visualize the calculation flow.

**Import Data:**

* Goods: 100 PCE Computer Parts
* HS Code: `8473.30.90`, Import Duty: `5%`
* FOB: USD `2,000`
* Freight: USD `100`
* Insurance: USD `50`
* KMK Rate: `Rp 16,000 / USD`

**Calculation Steps:**

1. CIF (Foreign) = `2,000 + 100 + 50` = **USD 2,150**
2. CIF (IDR) = `2,150 x 16,000` = **Rp 34,400,000**
3. Import Duty = `5% x 34,400,000` = **Rp 1,720,000**
4. Tax Base = `34,400,000 + 1,720,000` = **Rp 36,120,000**
5. VAT 11% = `11% x 36,120,000` = **Rp 3,973,200**
6. Article 22 Income Tax (API) = `2.5% x 36,120,000` = **Rp 903,000**
7. **Total Cash Payment = Rp 1,720,000 + Rp 3,973,200 + Rp 903,000 = Rp 6,596,200**

> [!IMPORTANT]
> For **BC 2.3 in a Bonded Zone**, Import Duty, VAT, and Article 22 Income Tax are **all suspended and not collected** thanks to the Bonded Zone facility. Total cash payment on BC 2.3 = **Rp 0**, but the obligation remains recorded in IT Inventory and must be realized through export or local sales via BC 2.5.

### 3.3 Special Calculation Provisions for BC 2.5 (Discharge to TLDDP / Local Market)

The **BC 2.5** document is used when processed products or capital goods from a TPB (Bonded Zone) are discharged into the domestic market (TLDDP). As customs suspension ends, the enterprise must pay Import Duty, VAT, and Income Tax. Pursuant to **PMK 131/PMK.04/2018 jo PMK 65/PMK.04/2021 Article 30**:

#### 1. Calculation Method Options (`kode_perhitungan`)
The system provides a **Calculation (`kode_perhitungan`)** field per goods line:

* **Option 1: Output Price / Harga Pengeluaran (Code `1`)**
  * **Duty Assessment Base (DPP BM)**: Based on the **Delivery Price / Selling Price** of the finished good.
  * **Tariff Heading / HS Code**: Uses the HS Code of the **Finished Good**.
  * **Formulas**:
    * `Import Duty = Delivery Price × Finished Good Duty Rate%`
    * `VAT (11%) = Delivery Price × 11%`
    * `Article 22 Tax = (Delivery Price + Import Duty) × PPh Rate%`
  * **Total Payable**: `Duty Value + VAT Value + Income Tax Value`.

* **Option 0: Inward Price / Harga Pemasukan (Code `0`)**
  * **Principle**: Tariff rates and levy amounts reference directly from the raw materials used in the **Raw Materials Tab (`bahan_baku_ids`)**.
  * When a finished good uses a mix of imported raw materials (ex-BC 2.3) and domestic raw materials (ex-BC 4.0), the **Goods Tariff** tab displays **4 distinct tax/duty rows**:
    1. **3 Levy Types from Imported Raw Materials (ex-BC 2.3)**:
       * **a. BM (Import Duty)**: `Σ (CIF IDR of Import RM × Duty Rate of Import RM%)`
       * **b. PPH (Import Income Tax)**: `(Σ CIF IDR of Import RM + BM) × PPh Rate%` *(API: 2.5%, Non-API: 7.5%)*
       * **c. PPN (Import VAT)**: `(Σ CIF IDR of Import RM + BM) × 11%`
    2. **1 Levy Type from Domestic Raw Materials (ex-BC 4.0)**:
       * **d. Local VAT (`PPNLOKAL`)**: `Σ (Price of Domestic RM) × 11%`
       * *(Domestic raw materials are exempt from Import Duty and Article 22 Tax)*.
  * **In Document Header Levies Table**: The system automatically summarizes all 4 levies as payable duties (Facility `1` DIBAYAR).

#### 2. Treatment of Non-Import / Purely Domestic Goods
* If finished goods are made purely from domestic/local raw materials (ex-BC 4.0 / `kode_asal_bahan_baku = 1`):
  * **Import Duty = 0% (Rp 0)**
  * **Article 22 Income Tax = 0% (Rp 0)**
  * **Only assessed with Local VAT (11%)**: `VAT = Delivery Price × 11%`.

#### 3. Article 22 Income Tax Provisions & Why CEISA API Returns No PPH
* **Why Does CEISA API (`ceisa.tarif`) Only Return BM and PPN?**
  * The CEISA OpenAPI endpoint `/openapi/tarif-hs` queries the **BTKI (Indonesian Customs Tariff Book)** which determines customs duties strictly per commodity HS Code.
  * Article 22 Import Income Tax is governed by the Directorate General of Taxes / Ministry of Finance based on the **taxpayer's entity qualification (importer API license status)**, not purely per HS Code. Hence, the CEISA API **never returns PPH tariff rows** under the `tarif-hs` endpoint.
* **Statutory 2.5% Rate Legal Basis:**
  * Pursuant to **PMK No. 34/PMK.010/2017 jo PMK No. 41/PMK.010/2022**:
    * Importers holding an **API (Importer Identification Number / NIB)**: Statutory rate of **2.5%** on the Tax Base (`PPh DPP = Delivery Price/CIF + Duty Value`).
    * Importers **Without API**: Statutory rate of **7.5%**.
    * Holders of **SKB (Article 22 Tax Exemption Certificate)**: Rate **0%** (Exempt facility).
  * In Bonded Zones (TPB), all operating enterprises hold valid API credentials. BZone automatically sets the standard **2.5%** default on imported goods or finished goods from imported inputs, while keeping the field editable for non-API or SKB scenarios.

#### 4. Anti-Duplicate UI Mechanism (In-Place Updates)
* When users change an HS Code, clear and re-select an HS Code, or click **"Tarik / Refresh Tarif CEISA"**:
  * BZone maps existing assessment lines (`BM`, `PPH`, `PPN`) and applies changes directly in-place via **`COMMAND.UPDATE` (`1, id, vals`)**.
  * Any duplicate lines from previous operations are automatically identified and purged via **`COMMAND.DELETE` (`2, id, 0`)**.
  * If the HS Code is emptied, lines are cleanly removed, preventing doubled records in the web client view.

### 3.4 Duty Treatment on Inter-TPB Transfers (BC 2.7)
Unlike BC 2.5, **BC 2.7** covers cargo transfers between Bonded Zones / TPBs:
* **Duty Facilities**: Import Duty is **Suspended (Facility Code 3)** and VAT/Income Tax is **Not Collected (Facility Code 5 or 6)**.
* VAT rate is recorded as $11\%$, but **Cash Payment = Rp 0** (all assigned to Facility Value) because the goods have not entered the open domestic market.

## 4. Guide for Selecting Duty Facility Codes

Every customs assessment for Import Duty, VAT, and Income Tax on TPB documents uses a **facility code** to indicate the payment status. Selecting the wrong code is the most common cause of TPB document rejection.

| Code | Status | When to Use | Legal Basis |
|---|---|---|---|
| **1** | **Paid (Dibayar)** | Import Duty on local sales from TPB to TLDDP via BC **2.5**. VAT/Income Tax remain fully collected. | Customs Law No. 17/2006, HPP Tax Law |
| **3** | **Suspended (Ditangguhkan)** | Import Duty on imported raw materials into a Bonded Zone via BC **2.3**. Not paid now, but recorded as a liability. | PMK 131/PMK.04/2018 on Bonded Zones |
| **6** | **Not Collected (Tidak Dipungut)** | VAT/Income Tax on BC 2.3 and local purchases into TPB via BC **4.0** (VAT non-collected under TPB facility). | Government Regulation No. 147/2000 jo. PMK 131/2018 |
| **8** | **Guaranteed (Dijaminkan)** | Import Duty on subcontract / repair release to external factory via BC **2.6.1**, secured with a bank guarantee. | PMK 272/PMK.04/2020 |
| **5** | **Exempted (Dibebaskan)** | Import Duty on imports under **SKA Form D / Form AK / Form E** preferential tariffs. | FTA Certificates: CEPA, ACFTA, IJEPA, etc. |
| **7** | **Already Paid (Sudah Dilunasi)** | Import Duty, VAT, or Income Tax already settled upfront (e.g., manual payment to the receiving bank before the document is sent). | Customs Law No. 17/2006 |

> [!TIP]
> Use this **quick guide** when in doubt:
> * Raw material import to Bonded Zone → **Code 3**
> * Local purchase into TPB → **Code 6** (for VAT)
> * Local market sale (BC 2.5) → **Code 1**
> * Outbound subcontract (BC 2.6.1) → **Code 8**
> * Import under preferential tariff → **Code 5**

## 5. Pre-Submission Verification Checklist

Before clicking **Send Document**, ensure all items below are checked to minimize **Rejection** risks.

* [ ] **26-digit Submission Number** generated automatically and looks reasonable.
* [ ] **Tax Rate Date** matches the applicable NDPBM KMK week.
* [ ] **TPB Operator** is positioned at Series 1 entity with a valid 16-digit NPWP.
* [ ] **Invoice** is at Series 1 order (type `380` / `PROFORMA`).
* [ ] **B/L or AWB** is at Series 2 order (type `705` / `740`).
* [ ] **Country flag code** is written in 2 uppercase ISO standard letters.
* [ ] **Total CIF value is not 0** and equals FOB + Freight + Insurance.
* [ ] **Exchange rate difference** between CIF in foreign currency and CIF in IDR is the multiplication with NDPBM KMK (not the bank rate).
* [ ] **8-digit HS Code** matches the physical goods description.
* [ ] **Duty facility code** (1/3/5/6/7/8) is appropriate to the transaction type.
* [ ] **Quantity and unit** in the goods tab are consistent with the packing list.
* [ ] **Signature and declaration** of data filling is checked by the PPJK or customs staff.
* [ ] **No unusual characters** (such as quote marks in numeric fields) that typically cause CEISA JSON schema parsing failures.

> [!IMPORTANT]
> If any of the items above is not satisfied, do not force the submission. Use the **Confirm** button to run BZone internal validation, and fix any displayed errors first.
